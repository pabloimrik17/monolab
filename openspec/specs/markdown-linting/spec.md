# markdown-linting Specification

## Purpose
Lint Markdown through markdownlint-cli in pre-commit and CI, with explicit config, root-anchored exclusions and a schema-version guard.

## Requirements

### Requirement: Markdown Linting Integration

The monorepo SHALL integrate markdownlint-cli into the pre-commit workflow via lint-staged to automatically lint all staged Markdown files before commit.

#### Scenario: Markdown files linted on commit

- **WHEN** a developer commits changes containing staged `*.md` files
- **THEN** markdownlint runs on those files via the lint-staged hook
- **AND** the commit proceeds if no unfixable errors are found

#### Scenario: Linting errors block commit

- **WHEN** a Markdown file has unfixable linting errors
- **THEN** the pre-commit hook fails
- **AND** the developer is shown the specific errors
- **AND** the commit is blocked until errors are resolved

### Requirement: Auto-fixing Capability

The markdownlint integration SHALL automatically fix fixable Markdown issues during the pre-commit hook execution.

#### Scenario: Auto-fix applied on commit

- **WHEN** a staged Markdown file has fixable issues (e.g., trailing spaces, inconsistent list markers)
- **THEN** markdownlint automatically fixes those issues
- **AND** the fixed content is staged for commit
- **AND** the commit proceeds successfully

### Requirement: Root-Anchored Path Exclusion

The markdownlint configuration SHALL support exclusion of specific paths via `.markdownlintignore` to prevent linting of generated, vendor, or AI-specific Markdown files. Agent, editor and OpenSpec directories SHALL be excluded only at the repository root, so nested product examples stay in scope.

#### Scenario: Ignored directories not linted

- **WHEN** Markdown files exist in excluded paths (the root `openspec/` and root agent/editor directories such as `.claude/` and `.opencode/`, or `node_modules/`, `dist/` and `coverage/` at any depth)
- **THEN** markdownlint does not process those files
- **AND** no linting errors are reported for them

#### Scenario: AI agent instruction files linted

- **WHEN** AI agent instruction files (AGENTS.md, CLAUDE.md) are modified
- **THEN** markdownlint lints them like any other Markdown file
- **AND** only the root agent/editor scaffolding directories are excluded via `.markdownlintignore`

#### Scenario: Auto-generated CHANGELOG files excluded

- **WHEN** CHANGELOG.md files exist in any package (auto-generated by Nx Release)
- **THEN** markdownlint ignores them via `.markdownlintignore`
- **AND** oxfmt ignores them via `ignorePatterns` in `oxfmt.config.ts`
- **AND** ESLint ignores them via `eslint.config.ts`
- **AND** they are never modified by any linting or formatting tool

### Requirement: Explicit Rule Configuration

The markdownlint integration SHALL read its rules from `.markdownlint.jsonc`, passed explicitly with `--config`, which extends `markdownlint/style/prettier` and declares a versioned `$schema` URL.

#### Scenario: Custom rules applied

- **WHEN** `pnpm run lint:markdownlint` or the pre-commit hook runs
- **THEN** markdownlint applies the rules in `.markdownlint.jsonc`
- **AND** a missing or unparsable `.markdownlint.jsonc` fails the run instead of falling back to defaults

#### Scenario: Schema version matches the engine

- **WHEN** CI runs `pnpm run lint:markdownlint:schema`
- **THEN** the run fails unless the `$schema` URL version equals both the root `markdownlint` version and the engine version that `markdownlint-cli` resolves
